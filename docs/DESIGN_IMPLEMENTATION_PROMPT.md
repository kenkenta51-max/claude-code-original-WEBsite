■ 1. 構成・原稿の扱い

構成と原稿は確定済みです。以下を守ってください。

・原稿の文言は変更しないでください。誤字脱字や明らかな表記ゆれだけを直し、直した箇所を完成報告に記載してください。
・セクションの順番と掲載内容は変更しないでください。体験型コンテンツやアニメーションのために、情報を削ったり、順番を入れ替えたりしないでください。
・体験型コンテンツは、内容が関係するセクションの中か、セクションの間に配置してください。新しく追加した場所は完成報告に記載してください。
・原稿にない文言（操作案内、ボタンの状態表示、エラー表示、代替テキストなど）だけは新しく作成してください。口調は原稿に合わせてください。
・「ここに説明文」などの仮置きは残さないでください。

架空サイトの場合は、原稿にあるブランド名、店名、商品名、人物名、所在地などの設定に合わせ、画像や追加の文言も統一してください。参考元の名称や、実在する企業の実績・受賞歴を流用しないでください。

制作前に、デザインの方針、体験型コンテンツ、主なアニメーション、必要な画像素材を簡潔に整理し、そのまま制作へ進んでください。

・セクションのつなぎ方

参考URLは、可能であれば実際に表示・スクロール・操作して確認してください。画像だけでは分からない動作を、確認した事実として扱わないでください。

分析した特徴を、今回のテーマと日本人向けの表現に合わせて展開してください。ただし、余白・文字の大きさ・見出し・写真・CTAは、3章のデザインの基本ルールを優先してください。参考資料がない場合は、テーマに合った独自のデザイン方針を決めてください。

■ 3. デザインの基本ルール

AIが作るデザインにありがちな「素人っぽさ」を防ぐため、以下を必ず守ってください。アニメーションや体験型コンテンツを加えても、このルールは崩さないでください。

【1】余白
セクションの上下の余白は、以下を基本にしてください。要素を詰め込まず、ゆとりを持たせてください。

・セクションの上下の余白：PC 120px／スマートフォン 72px
・コンテンツの最大幅：1080px（中央寄せ）
・スマートフォンの左右の余白：20px
・見出しと本文の間：PC 32px／スマートフォン 24px

セクションの境界を装飾や動きでつなぐ場合も、上下の余白を削らないでください。

【2】文字の大きさ
文字の大きさは「見出し・小見出し・本文」の3段階を基本にしてください。

・見出し：PC 40px／スマートフォン 26px、太字、行間1.4
・小見出し：PC 24px／スマートフォン 19px、太字、行間1.5
・本文：PC・スマートフォンとも16px、行間1.8

キャッチコピーも見出しの段階を使ってください。注釈やコピーライトなどの補足だけは、本文より小さくして構いません。それ以外の中途半端なサイズを増やさないでください。
動きで拡大・縮小する演出を使う場合も、止まったときの大きさはこの3段階にそろえてください。

【3】見出しの長さ
見出しは15文字以内が基本です。長い見出しはスマートフォンで3行になり、読みにくくなるためです。

原稿は変更できないため、15文字を超える見出しがある場合は、文言を変えずに完成報告で一覧にし、15文字以内の短縮案を添えてください。改行位置は、単語の途中で切れないように調整してください。

【4】写真
ファーストビューでは、メインビジュアルの写真または画像を1枚、横幅いっぱいに大きく使ってください。

小さい写真をパラパラ並べるだけのセクションは作らないでください。複数の画像を見せる場合も、主役になる1枚を大きく見せ、メリハリをつけてください。

【5】申し込みボタン（CTA）
申し込みボタンは、色も文言も1種類にそろえてください。

・文言：【制作条件】で指定した文言に統一する
・色：CTA専用の1色に統一し、CTA以外の要素には使わない
・配置：ファーストビュー、ページ中盤（お客様の声や体験型コンテンツの後など）、ページ最後の3か所を基本とする
・スマートフォンでは横幅いっぱい、高さ56px以上にする
・固定CTAや体験の結果画面に出すボタンも、同じ色と文言にする
・ホバーや押したときの動きは、すべてのCTAで同じにする

CTA以外のボタンは、CTAと見分けがつく色や形にしてください。

■ 4. UI・UXデザイン

配色、書体、余白、形状、画像表現をサイト全体で統一してください。

テーマを象徴するモチーフや特徴的な形を、ボタン、カード、背景、見出し、セクションの境界にも展開してください。

セクションごとに、伝える内容に合うレイアウトと見せ方を設計してください。同じカードの並びや装飾を繰り返すだけの構成にしないでください。

本文の読みやすさと操作の分かりやすさを確保してください。CTA以外のボタンは、押すと何が起こるか分かる文言にしてください。

必要な情報はホバーに依存させず、スマートフォンでも確認できるようにしてください。

■ 5. 画像・ビジュアル制作

FV、商品画像、背景、装飾など、必要な素材は画像生成ツールを使って作成してください。

画像生成前に、必要な素材と使用用途を整理してください。生成画像は、色味、光、質感、画風、世界観を統一してください。

FVのメインビジュアルは、横幅いっぱいで使うことを前提に、十分な解像度と構図で用意してください。

背景、主役、前景、装飾、影など、個別に動かす要素は分割してください。切り抜き素材は透過背景とし、輪郭の白い縁、欠け、不要な余白を確認してください。

状態別画像が必要な場合は、同じ対象の形、角度、光、縮尺、配置をそろえてください。切り替え時に位置や大きさが不自然に跳ねないようにしてください。

文字を重ねる画像には、文字を配置する余白を確保してください。重要な見出し、説明文、価格、日付は画像に焼き込まず、原則としてHTMLで表示してください。

PCとスマートフォンで構図を変える必要がある場合は、それぞれに適した素材を用意してください。

生成後は実際の表示サイズで確認し、必要に応じて再生成・修正・最適化してください。

画像生成ツールを使えない場合は、その制約を明示し、利用可能な素材やCSS・SVGによる表現で完成させてください。

■ 6. 体験型コンテンツ

テーマに合った、ユーザーの操作によって状態や結果が変わる体験を企画してください。触って楽しく、商品やサービスの理解につながる体験にしてください。

組み立てる、飾る、選ぶ、調理する、比較する、配置する、量を確かめるなど、商品やサービスの理解につながる操作を設計してください。

体験の数と複雑さはサイトの目的に合わせて調整してください。必要性の薄いミニゲームを増やすことは避けてください。

各体験について、以下を定義して実装してください。

・開始前の状態
・操作方法
・操作中の反応と進捗
・完了条件
・結果表示
・やり直し方法
・次の情報やCTAへのつながり

操作結果に合わせて、画像、数値、進捗、説明文、ボタンの状態を連動させてください。結果画面から申し込みへ進むボタンは、3章のCTAと同じ色と文言にしてください。

連打、操作途中の離脱、リサイズ、リセットでも状態が矛盾しないようにしてください。処理中の重複実行を防ぎ、操作できない状態は見た目と実際の動作に反映してください。

ドラッグ操作には、タップ・クリック・キーボードで使える代替操作を用意してください。スマートフォンの縦スクロールとドラッグが干渉しないようにしてください。

■ 7. アニメーション・演出

世界観と内容に合った、見て触って楽しめるアニメーションを実装してください。このサイトの主役となる部分です。

以下から適切な演出を選び、閲覧の流れに合わせて組み合わせてください。

・ページ表示時の段階的な登場
・スクロールに合わせた出現、移動、回転
・モチーフの浮遊、上昇、跳ねる動き
・セクションと連動した背景色の変化
・材料やパーツが集まる演出
・流れる文字や装飾
・ホバー時の浮き上がり、傾き、拡大
・クリックに応じた切り替え、展開、変形
・操作結果に連動した完了演出

単純なフェードインだけで終わらず、主要な場面にはテーマ固有の動きを設計してください。

動きの速度、距離、タイミング、緩急をサイト全体で調整してください。複数の演出が重なる場合は、視線の向かう場所が分かるようにしてください。

動きを加えても、3章の余白、文字の大きさ、写真、CTAのルールが崩れないようにしてください。アニメーションが終わった状態で、ルールどおりのデザインになっていることを確認してください。

オープニングを設ける場合は、スキップを用意してください。商品情報や主要CTAへのアクセス、ページ内リンクへの直接アクセスを妨げないようにしてください。ファーストビューのCTAは、演出の途中でもすぐに押せるようにしてください。

動きによって文字が読みにくくなる、操作を長く待たせる、過剰に点滅するといった状態は避けてください。

prefers-reduced-motionに対応し、動きを抑える設定でも内容と機能を利用できるようにしてください。

■ 8. 操作結果とCTAの連携

商品、数量、人数、サイズ、日時などを選択する場合は、その結果を合計表示や最終確認へ連動させてください。

必要に応じて、選択内容のコピー、リセット、再編集を用意してください。

体験を最後まで行わなくても、商品情報、価格、購入・予約・問い合わせの案内へ直接アクセスできるようにしてください。

すべての申し込み導線で、3章のCTAと同じ色と文言を使ってください。

架空サイトで外部送信先がない場合は、選択結果の確認やコピーまでをデモとして実装し、実際に購入・予約・送信が完了したと誤認させないでください。

■ 9. HTML・CSS・JavaScript

基本はHTML・CSS・JavaScriptで実装してください。

・HTMLにlang="ja"を設定する
・適切な見出し階層と意味のあるタグを使用する
・CSSは<style>、JavaScriptは<script>にまとめる
・主要な配色、余白、文字サイズはCSS変数で管理する
・用途ごとにコードを整理し、後から編集しやすくする
・グローバル変数や重複処理を必要以上に増やさない
・通常のLPでは、ビルドなしで開ける形式を基本とする

3章のルールは、以下のようなCSS変数で管理し、個別の数値を直接書かないでください。

・セクションの上下の余白（PC・スマートフォン）
・見出し、小見出し、本文の文字サイズと行間
・CTAの色
・コンテンツの最大幅と左右の余白

CSS、標準JavaScript、SVG、Canvas、Web Animations APIなどから適切な技術を選んでください。

複雑な連動演出にはGSAP・ScrollTrigger、実際の3D表現にはThree.jsなどを必要に応じて使用して構いません。使用する場合は、目的、容量、納品形式との整合性を確認してください。

ツールやライブラリの導入自体を目的にせず、必要な表現と保守性に合う構成を選んでください。

■ 10. データと状態の管理

価格、商品名、人数の目安、日付、連絡先、CTAの文言とリンク先などは、変更しやすい共通データとして管理してください。

同じ情報を複数箇所で表示するときは内容を一致させてください。選択状態は共通の状態データから画面へ反映し、表示同士の食い違いを防いでください。

日本向けの日付判定はAsia/Tokyoを基準にしてください。期間限定サイトでは、受付前・受付中・締切後の表示と操作を定義してください。

ブラウザに状態を保存する場合は、保存対象と有効期間を決め、保存できない環境でも主要機能が動作するようにしてください。個人情報を不用意に保存しないでください。

■ 11. レスポンシブ・アクセシビリティ

PC・タブレット・スマートフォンに対応してください。

・画面幅に応じて、余白と文字サイズを3章のPC用・スマートフォン用の値で切り替える
・横方向のはみ出し、文字切れ、要素の重なりを防ぐ
・画像の縦横比と切り抜き位置を調整する
・タップ領域は原則44px四方以上を目安に確保する（CTAはスマートフォンで高さ56px以上）
・固定ヘッダーや固定CTAが本文を隠さないようにする
・画像に用途に合った代替テキストを設定する
・装飾画像は読み上げの妨げにならないようにする
・キーボード操作と明確なフォーカス表示に対応する
・文字と背景のコントラストを確保する
・動的な結果は必要に応じて読み上げに通知する

メニューやモーダルには、開閉状態の通知、適切なフォーカス移動、Escapeキーによる閉じる操作、閉じた後のフォーカス復帰を実装してください。

■ 12. 表示速度・安定性

FVの主要画像を優先して読み込み、下部の画像や体験用素材は適切なタイミングで読み込んでください。

・表示サイズに合った画像解像度を使う（横幅いっぱいのメインビジュアルは、画面幅に合わせて複数サイズを用意する）
・WebPやAVIFなど、用途に適した形式を選ぶ
・透過素材は必要な透明度を維持する
・画像の領域を事前に確保し、レイアウト移動を防ぐ
・日本語フォントの種類とウェイトを増やしすぎない
・画像やフォントの読み込み失敗に備える

アニメーションは主にtransformとopacityを使用し、頻繁なレイアウト計算を避けてください。

画面外やバックグラウンドでは、不要なアニメーション、Canvas描画、タイマー処理を停止または軽減してください。高解像度端末でも描画負荷が過大にならないようにしてください。

JavaScriptや外部サービスの一部が失敗しても、本文と主要導線へアクセスできるようにしてください。

公開サイトでは、LCP 2.5秒以内、CLS 0.1以下、INP 200ミリ秒以下を目標とし、測定できる範囲で確認してください。スコアだけを目的に、必要な表現を一律に削除しないでください。

必要な機能を実際に動作する状態にしてください。

・ページ内ナビゲーション
・モバイルメニュー
・FAQやモーダルの開閉
・商品やタブの切り替え
・入力チェック
・操作結果の表示

リンク先や動作のないボタンは残さないでください。

ページタイトル、meta description、viewport、faviconを設定してください。公開URLが決まっている場合は、OGP画像、OGP情報、canonicalも適切に設定してください。未確定のURLを実在するURLとして記載しないでください。

GitHub Pagesなどのサブディレクトリ公開では、画像・リンク・スクリプトが正しく動く相対パスを使用してください。

■ 14. 納品形式

指定された形式で納品してください。

【完全単一HTML】
HTML・CSS・JavaScript・画像などを1つのHTMLへ埋め込み、外部ファイルやネット接続なしで表示・操作できるようにしてください。
外部フォントを埋め込めない場合は、適切なシステムフォントを使用してください。

【HTML＋assets】
HTML内にCSS・JavaScriptをまとめ、画像などをassetsフォルダに整理してください。公開時の読み込み速度とキャッシュを考慮してください。

【両方】
公開用の「HTML＋assets」と、保存・受け渡し用の「完全単一HTML」を用意し、内容と機能をそろえてください。

ファイルサイズと外部依存の有無を納品時に明示してください。

■ 15. 検証

実装後はブラウザで表示・操作を確認し、不具合を修正してください。

幅375px、390px、768px、1440pxを目安に、以下を確認してください。

・初回表示と再訪時の表示
・画像、文字、余白、重なり
・横方向のはみ出し
・ページ内リンクと固定ヘッダーの位置
・メニュー、ボタン、フォーム
・体験の開始、進行、完了、リセット
・連打と操作途中の画面移動
・画面幅変更や端末の向き変更
・キーボード操作
・動きを抑える設定
・画像や外部素材の読み込み失敗
・JavaScriptエラー

あわせて、3章のデザインの基本ルールを以下のとおり確認してください。守れていない項目は、1項目ずつ修正しては確認してください。まとめて直すと、どれかが抜けやすくなります。

・余白：セクションの上下の余白が、PC 120px／スマートフォン 72pxになっている
・文字の大きさ：見出し・小見出し・本文の3段階にそろっている（補足の文字を除く）
・申し込みボタン：すべてのCTAが同じ色・同じ文言・同じ動きになっている
・写真：ファーストビューのメインビジュアルが1枚、横幅いっぱいで大きく使われている
・見出しの長さ：スマートフォンで3行以上になっている見出しがない。15文字を超える見出しを一覧にした
・原稿：原稿の文言が変わっていない

Playwrightなどのブラウザ検証ツールを利用できる場合は、主要操作と画面幅別のスクリーンショットを確認してください。

Lighthouse、PageSpeed Insights、axe-coreなどを利用できる場合は、表示速度とアクセシビリティを確認し、主要な問題を修正してください。

実機で確認していない場合は、実機確認済みと記載しないでください。未実施の検証や測定値を推測で補わないでください。

■ 16. 制作の進め方・完成報告

通常のデザイン判断、素材制作、実装、修正は、制作者の判断で進めてください。作業ごとの確認は不要です。

制作を成立させるために不可欠な情報が不足している場合や、公開・課金・外部送信など別途承認が必要な操作は、必要な内容を明確にしてください。それ以外の作業は継続してください。
